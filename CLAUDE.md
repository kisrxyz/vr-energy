# Тренажёр переключений (vr energy)

Демо-бета тренажёра оперативных переключений для энергетиков: собрать схему подстанции в 2D,
выполнить переключения в 2D или в 3D/VR (шлем Meta Quest через WebXR), получить блокировку
или аварию за ошибку и отчёт. Цель — показывать заказчикам и получить платный пилот.
Рынок — Казахстан и СНГ, интерфейс только на русском (позже — казахский).
История идеи, выводы анализа, план недели и статус — в `docs/context.md`. Прочитай его перед большими задачами.

## Команды
- `npm install` — один раз после скачивания
- `npm run dev` — запуск на компьютере, http://localhost:5173
- `npm run dev:vr` — https в локальной сети, чтобы открыть с шлема (сертификат самоподписанный — в шлеме нажать «Продолжить»)
- `npm test` — автотесты движка (без браузера). Запускать после любой правки в `src/core/`
- `npm run build` — сборка в `dist/`; при пуше в `main` GitHub Actions сам выкладывает на GitHub Pages
- `npm run check3d` — каждая готовая схема в 3D в headless Chrome: вызовы отрисовки и треугольники в «Обзоре» и «Пешком» (см. «Проверка в браузере без шлема»)
- `npm run e2e` — автопроходка собранного сайта в headless Chrome: все задания через интерфейс, типовые ошибки (`-- --only=poly --shots`)

## Как работаем
- Каждая задача — ветка от свежего `main`, в конце PR с описанием на русском: что сделано, как проверить, что не успел.
  Если нужная работа ещё в несмерженном PR — так и написать в PR, ветку брать от неё.
- Фоновых агентов-проверяльщиков не запускать; `npm test` и `npm run build` (для 3D — `npm run check3d`) — самому.
- Правила движка 1–16 не менять. Сомнение в правиле — вопрос в `docs/questions-for-teacher.md`, не код.
- В конце обновить CLAUDE.md и `docs/context.md`, если поменялось устройство или статус.
- Сайт: https://kisrxyz.github.io/vr-energy/ (репозиторий kisrxyz/vr-energy), выкладка — при слиянии в `main`.

## Устройство
Один движок — два вида. Всё на чистом JavaScript (ES-модули), без фреймворков; 3D — three.js 0.160.
- `src/core/elements.js` — типы элементов (TYPES), категории палитры (CATS), поиск, точки подключения, повороты, классы напряжения, создание схемы
- `src/core/glossary.js` — тексты «Подробнее» для каждого типа (что это, зачем, переключения, поведение в тренажёре, вопрос преподавателю)
- `src/core/samples.js` — готовые схемы (ПС 110/10 кВ, ТП 10/0,4 кВ, ПС 110/35/10 кВ, VR-полигон ЗРУ-10 кВ) и задания к ним
- `src/core/engine.js` — движок: топология, напряжение/земля, правила, защита, задания, запись эталона (класс `Trainer`). **Без DOM** — должен работать в Node.
  Дополнения — `tr.use(addon)`: guard (механическая блокировка), done, finish, hint, stepText, checkWhere (место проверки указателем в журнале), event; правила движка они не меняют
- `src/core/permit.js` — VR-полигон «Допуск к работе» (дополнение `Permit`): предметы, места для них, СИЗ, плакаты, замок, порядок технических мероприятий. Без DOM.
  Предупреждение «без СИЗ» в свободном режиме — не чаще раза в 15 с (в журнал — каждый раз). Запись эталона (режим инструктора) в полигоне выключена: мероприятия она не записывает
- `src/core/explain.js` — тексты «почему опасно» к ошибкам полигона (проверяет преподаватель)
- `src/view2d/scheme2d.js` — отрисовка схемы в SVG и редактор (мышь, касания); выделение — один элемент или провод `{type, id}` либо группа
  `{type:'group', els, wires}`: Shift/Ctrl + перетаскивание по пустому месту — рамка, Shift/Ctrl + щелчок — добавить/убрать, кнопка «Выделение» (телефон)
- `src/core/edit.js` — группа без DOM: рамка (`inRect`), перенос (`grip`/`moveGrip`: свои провода целиком, к остальным тянутся), поворот вокруг центра,
  копия и вставка (новые id, имена через nextName при совпадении), удаление. Буфер Ctrl+C — в памяти и `ts.clip`; каждая операция — один шаг «Отменить»
- `src/view3d/view3d.js` — 3D-сцена и VR (контроллеры, щит с заданием, меню тележки, эффекты, слияние деталей); на площадке — «Обзор» или «Пешком» (кнопка),
  общая подпись под курсором и прицелом — `targetText`
- `src/view3d/models/<тип>.js` — построитель 3D-модели каждого типа; интерфейс и реестр — `models/index.js`, фигуры — `models/kit.js`
- `src/view3d/room.js` — помещение полигона: стены, свет, ячейки КРУ в ряд (тележки, ЗН, лампы, ИНН), шины, стенд, места для предметов, столкновения
- `src/view3d/items.js` — предметы в руках: модели, стенд/рука/пол/место, взять, отпустить, повесить, коснуться (ноутбук и шлем); перчатки и каска надеваются сразу при взятии
- `src/view3d/walk.js` — пешком на ноутбуке, полигон и площадка: WASD (≈3 м/с), мышь с захватом курсора (отказ в ~1 с после Esc не считается; `lockChanged`/`lockFailed` проверяются без настоящего захвата), прицел и подсказки поверх 3D.
  Полигон: E/Q — предметы и аппараты. Площадка: E или щелчок — как щелчок мышью (до аппарата и провода 6 м, щита 9 м), V/P — указатель/ПЗ, щелчок по земле ближе 25 м — перейти
- `src/view3d/world.js` — мир для ходьбы (и стика в шлеме): `resolve(x, z, r)`, `walkable(x, z, r)`, `start`; препятствия площадки — детали моделей выше 0,5 м,
  начинающиеся ниже головы (под проводами и шинами можно ходить), близкие сливаются (`footprints`); граница — ограждение с воротами (`makeYardWorld`)
- `src/ui/panels.js` — боковая панель, журнал, окна (отчёт, «Схемы» и файл, справка)
- `src/ui/myschemes.js` — «Мои схемы» в localStorage: список `ts.mySchemes`, схема `ts.my.<id>`; старый слот `ts.my` переносится в список
- `src/ui/sound.js`, `src/ui/store.js` — звук и localStorage
- `src/ui/diag.js` — журнал ошибок и запись VR-теста (FPS, отметки, отчёт для справки)
- `src/app.js` — режимы, правка схемы, связка движка с видами; `src/main.js` — вход, `window.TS` для консоли и проверок
- `src/styles.css` — оформление, светлая и тёмная темы, переменные цветов (других цветов в коде нет)
- `tests/engine.test.js` — сценарии: эталонные задания, типовые ошибки, новые элементы, полнота библиотеки, «Мои схемы», полигон (мероприятия, ошибки, ПЗ, замок)
- `tools/check3d.mjs` — проверка 3D в headless Chrome (`npm run check3d`)
- `docs/context.md` — история идеи, выводы анализа, что сделано по версиям, ограничения, статус; `docs/vr-test-checklist.md` — чек-лист теста в шлеме на 15–20 минут
- `docs/elements-review.md` — сверка библиотеки с типовыми ПС, РП, ТП; `docs/questions-for-teacher.md` — открытые вопросы по правилам

## Элементы (27 типов, `TYPES` в elements.js)
- Источники: энергосистема `source`, генератор `gen`.
- Шины и линии: шина `bus`, воздушная линия `ohl`, кабельная линия `cable` (двухполюсные, длина в км).
- Коммутационные: выключатель `breaker`, выкатной выключатель КРУ `cart`, разъединитель `disconnector`, выкатной разъединитель `cartdisc` (тележка СР, ТН),
  выключатель нагрузки `loadbreak`, отделитель `od`, ЗН `earth`, короткозамыкатель `kz`, рубильник 0,4 кВ `knife`, автомат 0,4 кВ `acb`.
- Трансформаторы: двухобмоточный `transformer`, трёхобмоточный `tr3` (выводы слева/справа — по свойствам kv2/kv3), ТСН `tsn`, реактор `reactor`.
- Защита и измерения: ТН `vt`, ТТ `ct`, ОПН `arrester`, предохранитель `fuse`, переносное заземление `pz`.
- Потребители: нагрузка `load`, двигатель `motor`, конденсаторная батарея `capacitor`.
- Классы (`cls`): source, bus, switch (sw, lb — рвёт нагрузку, prot — отключает КЗ, cart — тележка), earth (ek: earth/kz/pz),
  transformer (wnd — обмотки), link (ТТ, реактор, КЛ, ВЛ — проводник без коммутации), passive (ТН, ОПН), load (consumer — потребитель).
- Новый тип: TYPES + BOX + PALETTE, символ в `symbolSVG`, модель `models/<тип>.js`, текст в glossary.js, тест. Тест «Library completeness» проверит.

## Модель данных
- Сетка в клетках. Элемент: `{id, t, x, y, r, name, p, on, pos}`; `r` — поворот ×90° по часовой; `on` — нормальное положение; `pos` — положение тележки (work/test/repair).
- Переносное заземление в тренажёре — псевдоэлемент с id `'pz:' + id провода или шины` (ключи в init/target задания). В одной точке (узле) — одно ПЗ;
  задание сравнивает ПЗ по точке, а не по отрезку провода. Проверка указателем по проводу записывается в эталон по id провода. ПЗ из палитры ставится на провод в любой точке.
- Провод: `{id, a, b, vf}` — соединяет **только концы**; рисуется L-образно, `vf` = сначала вертикально.
- Узел = точки, связанные проводами и шинами. Ребро графа = включённый аппарат или трансформатор.
- Задание: `{init, target, initPos, targetPos, steps, keep, requireCheck}` — `keep` = потребители, которых нельзя обесточивать;
  шаг `{op: on|off|check|pos, id, pos?}`; `pos` — переместить тележку.
- Полигон: у схемы `room = {kind:'zru', cells:[{n, title, kind: input|line|vt, cart, earth, up, lo}]}` — ячейки КРУ в ряд; `up`/`lo` — провода у верхних (шинных)
  и нижних (линейных) разъёмных контактов. У задания `measures` (мероприятия `{k, stage, id?, wire?, pos?, poster?, at?, title?}`, k: ppe, off, rack, sign, lock, check,
  earth, fence) и `workCell`; шаги без аппаратов — `{op: wear|hang|unhang|lock|unlock|fence|unfence, item?, poster?, at?}` (`FIELD_OPS`).
  Места (mount): `drive:N`, `door:N`, `earth:N`, `cart:N`, `shutter:N`, `contact:N:lo|up`, `zone:N`, `fence`. Отсек тележки открыт только в ремонтном положении.
- В 3D: 1 клетка = 1,25 м, провода на высоте 3,4 м; неподвижные детали сливаются по материалам (`mergeStatic`), подвижные части — внутри себя (`compactParts`),
  все подписи — одна сетка (`makeLabels`), все лампы положения — одна InstancedMesh (`makeLamps`); щелчок/луч ловят невидимые коробки (`makeProxies`, у проводов тоже).
  Держать ≤ ~200 вызовов отрисовки на кадр — это шлем. Сейчас (`npm run check3d`, renderer.info.render.calls): ПС 110/10 — 101, ТП — 49, ПС 110/35/10 — 167.
  Пешком по площадке от ворот (headless, 1366×860): ПС 110/10 — 84, ТП — 46, ПС 110/35/10 — 110; мир для ходьбы — данные, новых сеток нет.
  Полигон: 1 м = 1 м; на ноутбуке 49–72 вызова от первого лица (58 у входа), 89–95 в обзоре; в шлеме — 108–142 за оба глаза (эмулятор Quest 3).
  Начинка тележки видна только выкаченной; невидимые коробки (proxy) не сливаются; предметы помечены `userData.dyn` и тоже не сливаются.

## Правила логики (подтверждает преподаватель — не менять без него)
1. ЗН на участок под напряжением — авария (дуга, КЗ).
2. Разъединитель на заземлённый участок под напряжением — авария.
3. Выключатель на заземлённый участок — КЗ, отключается защитой.
4. Разъединителем нельзя разрывать или включать ток нагрузки — авария. Ненагруженные шины и трансформаторы — можно.
5. ЗН без проверки отсутствия напряжения указателем — нарушение порядка (если правило включено).
6. В задании потребитель из `keep` потерял питание — ошибка «перерыв питания».
7. При КЗ отключаются ближайшие выключатели на границе зоны КЗ, через которые она питается; нет таких — отключение со стороны энергосистемы.
С блокировками операции 1–4 не выполняются, но считаются ошибкой. Логика — в `Trainer.analyze` и `Trainer.clearFault`.

Новые правила 0.2 (сделаны как бесспорные, ждут подтверждения преподавателя — `docs/questions-for-teacher.md`):
8. Предохранитель при КЗ перегорает вместо выключателя выше; перегоревший отключён до замены. Снимать и ставить — без нагрузки.
9. Выключатель нагрузки рвёт ток нагрузки, но не ток КЗ: КЗ за ним отключает выключатель выше или предохранитель.
10. Тележку КРУ перемещают только при отключённом выключателе; перемещение тележки = операция разъединителем.
11. Рубильник без дугогасительных камер — как разъединитель, с камерами — рвёт ток нагрузки.
12. ПЗ — правила ЗН. Отделитель вручную — как разъединитель; короткозамыкатель на напряжение — искусственное КЗ.
Где правило зависит от практики предприятия — простейшее поведение и `// TODO преподаватель:` с вопросом.

Правила VR-полигона 0.3 (`Permit`, только в схеме с `room`; тексты «почему опасно» — `explain.js`, ждут преподавателя):
13. Операция с аппаратом и проверка указателем без диэлектрических перчаток и каски — нарушение (в журнале каждый раз, в задании — одна ошибка).
14. Замок на приводе ячейки механически не даёт переключать её тележку и выключатель (сильнее настройки «Блокировки»); попытка — ошибка «блокировка».
15. Включение выключателя или вкатывание тележки под плакатом «Не включать! Работают люди» — ошибка «охрана труда».
16. Задание с мероприятиями: этапы 0 СИЗ → 1 отключить, выкатить → 2 «Не включать», замок → 3 проверка → 4 ЗН или ПЗ → 5 «Заземлено», «Работать здесь»,
    ограждение, «Стой! Напряжение». Мероприятие раньше предыдущего этапа — одна ошибка; заземление без проверки — отдельная; не сделанное к концу — «пропущено».
    Плакат, замок, ограждение не у места работ — ошибка. Задание выполнено, когда сделаны все мероприятия. Ошибка 'safety' стоит −10, как нарушение порядка.

## Проверка в браузере без шлема
Зависимостей не добавляют: Node 22+ (встроенный WebSocket) и установленный браузер. Браузер ищет `tools/cdp.mjs`:
`CHROME_PATH` (или `CHROME`) → `/opt/pw-browsers` → стандартные пути Chrome и Edge в Windows, Linux, macOS; не найден — сообщение и код 2.
- `npm run e2e` (`tools/e2e.mjs`, помощник в странице `tools/e2e-page.js`): сборка + `vite preview` (то, что уйдёт на сайт, порт от 5181),
  все задания всех готовых схем через интерфейс по плану `src/core/plan.js` (2D — щелчки по схеме, меню тележки, кнопки; полигон — пешком,
  прицел, E/Q) — каждое 100 баллов; по типовой ошибке на схему; ошибки консоли, журнал diag.js, «undefined/NaN» на экране — сбой. Итог — таблица, код ≠ 0 при сбое.
  Флаги: `--no-build`, `--only=<схема|проверка>[,…]` (ps110, tp10, ps35, poly, tasks, errors…), `--shots` — снимки в `e2e-out/` (в .gitignore).
  npm сам забирает `--only`, поэтому так: `npm run e2e -- --only=poly --shots` (или `npm run e2e --part=poly --shots`).
- `npm run check3d` (`tools/check3d.mjs`): каждая схема из `SAMPLES` в 3D — «Обзор» и «Пешком» (полигон — пешком у входа и «Обзор»),
  таблица вызовов отрисовки и треугольников; > 200 вызовов, > 300 тыс. треугольников или ошибки — код 1. FPS в headless не мерить — он программный.
Свою проверку делать тем же рецептом:
- Vite — на свободном порту (скрипт берёт от 5180). **5173 не трогать**: там часто работает `npm run dev` владельца, не останавливать его.
- Chrome: `--headless=new --remote-debugging-port=0 --user-data-dir=<временная папка> --use-angle=swiftshader --enable-unsafe-swiftshader --window-size=1366,860`;
  адрес CDP — строка `DevTools listening on ws://…` в stderr. Дальше `Target.createTarget` → `Target.attachToTarget {flatten:true}` → `Page.navigate`
  и `Runtime.evaluate {awaitPromise:true, returnByValue:true}`.
- В консоли страницы всё через `window.TS` (`src/main.js`): `TS.app.chooseScheme('ps110' | 'tp10' | 'ps35' | 'poly')`, `TS.app.setMode('3d')`,
  `await TS.app.v3.show()`; движок — `TS.app.tr`, 3D — `TS.app.v3` (`toggleWalk()` — «Пешком»/«Обзор» на площадке, `toggleTopView()` — «Обзор» в полигоне).
- Вызовы отрисовки: подождать 2 кадра (`requestAnimationFrame` дважды) и прочитать `TS.app.v3.renderer.info.render.calls` — счётчик последнего кадра.
- Захват мыши в headless не работает. Вместо него — `TS.app.v3.walk.lockChanged(true)`; повернуться — `walk.look(dx, dy)` или задать `walk.yaw`, место — `walk.reset({x, z, yaw})`.
- WASD и E: `document.dispatchEvent(new KeyboardEvent('keydown', {code: 'KeyW'}))`, через нужное время — `keyup` (ходьба идёт в кадре, `walk.step`);
  E и Q срабатывают на `keydown` (без `repeat`), пока ходьба включена и окно (`#modal`) закрыто. Что под прицелом — `walk.updateAim()` и подпись `targetText`.
- Ошибки страницы — `TS.Diag.errors()` (журнал в localStorage; профиль Chrome временный, журнал каждый раз пустой).
- WebXR в headless нет: шлем — эмулятор iwer (Quest 3) в обычном Chrome или настоящий шлем по `npm run dev:vr` и `docs/vr-test-checklist.md`.

## Известные ограничения (так задумано, не чинить без задачи)
- Токов нет: только напряжение, земля и связность. АВР, подробной РЗА, вторичных цепей (ТН, ТТ) и автоматики ОД+КЗ нет.
- Зеркального отражения элементов нет (в ПС 110/35/10 у Т1 выводы переставлены: слева 10 кВ, справа 35 кВ).
- Данные только в браузере (localStorage и файл .json); сервера и журнала учеников нет.
- Цвета классов напряжения условные — ждут преподавателя.
- Запись эталона (режим инструктора) в полигоне выключена: мероприятия допуска она не записывает.
- Полигон: модели простые; ограждение одно и ставится целиком; указатель не проверяют на исправность; шторки отсека не открываются,
  кабельный отсек закрыт; на телефоне ходьба только щелчком по полу; руки без контроллеров в шлеме не поддерживаются.
- Подробнее и по версиям — «Ограничения 0.2» и «Ограничения 0.3» в `docs/context.md`.
